## What was exercised

Every registered API has a successful scenario. Applicable routes also receive anonymous-access, cookie-CSRF, employee/admin role restriction, and invalid-input checks. A coverage gate fails if a newly registered API lacks a successful feature scenario.

Workflows exercise login/CAPTCHA/OTP, password recovery and first-password changes; employee workspace, profile, calendars and inbox; employee creation, access, archive, restore and permanent deletion; leave submission, conflicts, approval, cancellation, bulk decisions and undo; cash requests, terms acceptance, cancellation and disbursement; payroll preparation, bonuses, payment holds, payment, duplicate protection, undo, quarterly additions and email; manual/bulk attendance, correction, offline capture, forced checkout and idle days; reports, backups, audit actions, settings, Insights and fingerprint testing.

The browser checks run the production React build in headless Edge and cover every administrator sidebar page and employee section, protected controls, refresh feedback, contact-editor cancellation, mobile navigation, sign-in/CAPTCHA, the complete password-recovery UI, OTP login, and initial password replacement.

## Defects found and fixed

1. The employee payroll-summary email API referenced an undefined database variable when resolving recurring additions. It now obtains the configured connection before building the summary. Backend lint now checks undefined variables so this class of error is caught earlier.
2. Attendance date filters silently ignored malformed dates and accepted reversed ranges. They now return HTTP 400.
3. Invalid overview dates could cause a server error; invalid audit calendar dates were accepted. These now return HTTP 400 using calendar-date validation.

## Isolation and verification boundaries

HTTP tests execute the actual Express routers, authentication, CSRF and application handlers against synthetic records and an in-memory database double. The double supports query, update, projection and transaction behavior used by the scenarios, but does not establish MongoDB Atlas transaction/index behavior.

Email provider calls and the native fingerprint matcher protocol are simulated. Browser checks use API fixtures produced from successful HTTP tests; they do not connect the browser to a live database. No real employee account, payroll payout, leave decision, email delivery or biometric record is changed.

These results do **not** certify physical reader accuracy, Windows driver/FingerJet installation, real mailbox delivery, hosted service configuration, browser print dialogs or real download destinations. Those require environment/device acceptance testing. The local scanner/cloud-hosting integration limitation remains.

## Repeat the checks

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run test:api
npm.cmd run test:browser
```

The browser command needs Microsoft Edge at the configured Windows path, a production build, and the local fixture file generated by the API test. It launches only a local fixture server. Browser profiles use ignored *.local directories.
